For deep Wasp mechanics (spec, operations, auth, imports, dev loop) read [`docs/wasp-fundamentals.md`](docs/wasp-fundamentals.md) — don't duplicate it here.

## Project

**proto-stack** — a template for validating product ideas fast. Wasp 0.25 (TypeScript Spec, `main.wasp.ts`), Postgres, a flat "paper" design system, and three skills (`/prototype`, `/brand`, `/ship`). The goal is speed to a demoable prototype, spending nothing on external services until an idea graduates.

When you spin up a new idea, run **`/prototype`** first — it renames the app and builds the walking skeleton.

## Non-negotiable rules

### The Wasp Spec (`main.wasp.ts`)

- Build it from constructors imported from `@wasp.sh/spec` (`app`, `route`, `page`, `query`, `action`, `job`, `api`, `ref`).
- `@wasp.sh/spec` is **generated** (`file:.wasp/spec/`) — never install it from npm. Run `wasp install` after a clean/clone.
- Reference app code with `import X from "./src/..." with { type: "ref" }`. Paths are relative to the `.wasp.ts` file and must resolve inside `src/`.
- `route(name, ...)` takes an explicit name; `query`/`action`/`api`/`job` take their name from the imported identifier.
- Entities are strings: `entities: ["User"]`.

### Imports in `.ts` / `.tsx`

- Wasp imports use `wasp/...` (e.g. `wasp/client/auth`, `wasp/server`, `wasp/entities`). Never `@wasp/...`, never `@src/...`.
- Everything else uses **relative** paths — there is no `@/` alias.

### Operations (queries & actions)

Copy [`src/user/operations.ts`](app/src/user/operations.ts) — it is the reference shape. Every operation, in this order:
1. Checks auth **first**: `if (!context.user) throw new HttpError(401)` as the first statement (or is marked `// public-operation:`). Wasp exposes a callable endpoint for every operation, so this is the real security boundary — `authRequired` only gates the page. Don't do work for an unauthenticated caller.
2. zod-parses its input next, before using it (or is marked `// no-input:`).
3. Scopes every read/write to `context.user.id` — never trust an entity id from the client (IDOR). See [`docs/security.md`](docs/security.md).

Put operations in a file named `operations.ts` (or `queries.ts` / `actions.ts`) — security-lint keys the auth/input checks on those names. Client: `useQuery(...)` for reads; `await theAction(args)` for actions (import from `wasp/client/operations`). Conventions for state, loading/empty/error, and forms live in [`docs/frontend.md`](docs/frontend.md); query/index/pagination rules in [`docs/performance.md`](docs/performance.md).

### UI

- Compose from the primitives in `src/client/components/ui` (`Container`, `Section`, `Heading`, `Card`, `Button`, `NavLink`, `Alert`). Don't hand-roll buttons/cards.
- **Tokens only** — no raw Tailwind colours (`text-blue-500`), no hex literals. `brand-lint` fails the build on either.
- No shadows, no gradients while the design is `flat` (brand.config.json). Depth is hairline borders + inverted bands.
- Never edit design tokens by hand for a rebrand — that's `/brand`. Never edit `src/brand/palette.ts` — it's generated by `npm run brand:mirror`.
- No generated-page tells: no mono-caps eyebrows, no 01/02/03 feature grids, no pill rows restating the subhead. Sentence case. Lucide icons, no emoji. Keep the built-in accessibility (focus rings, `role` on alerts, `aria-hidden` on decorative icons). See [`docs/design-principles.md`](docs/design-principles.md) and [`docs/design-system.md`](docs/design-system.md).

### Comments

Bias is **no comment**. AI bloats code with narration; this repo doesn't ship it.

- **Default to none.** Names and structure carry the meaning. If a comment
  restates what the code does (`// loop over users`), delete it — or fix the name.
- A comment earns its place only by saying what the code **cannot**: a non-obvious
  *why*, an external constraint or workaround (link it), or a consequence warning
  ("moving this breaks scroll restoration").
- **Never:** narrating comments, section-banner comments, JSDoc on internal
  functions with self-evident params, changelog comments ("added X"),
  commented-out code, or TODOs without a concrete action.
- The lint markers (`// public-operation:`, `// no-input:`, `// external-api:`)
  are functional annotations, not comments — always keep them.
- The template's own teaching comments (the `operations.ts` header, the Main.css
  `overflow-x` block) are deliberate constraint docs and stay. New feature code
  follows the strict rule.

### Env & auth

- `main.wasp.ts` **reads `.env.server` itself** at compile time (Wasp injects only `NODE_ENV` into the spec). So after editing `.env.server`, **restart `wasp start`** for it to take effect.
- Google OAuth turns on automatically when `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET` are both set. The compile log prints enabled/disabled.
- The `Dummy` email provider prints verification/reset emails to the wasp server console. `SKIP_EMAIL_VERIFICATION_IN_DEV=true` skips the click entirely in dev.
- Provider setup (Google, Resend, Railway) lives in [`docs/providers.md`](docs/providers.md) with exact console URLs — follow it, don't improvise console steps.

### Dependencies

- Add with `npm install <pkg>` in `app/`. Never via `main.wasp.ts`.
- `app/.npmrc` sets `min-release-age=7` — packages published in the last 7 days are refused (supply-chain guard). If an install is rejected as too new, pin an older version rather than disabling the guard.

## After changes

- Edited `main.wasp.ts` or `schema.prisma`? Restart `wasp start` so types regenerate.
- Schema change? `wasp db migrate-dev "message"`.
- Ran `wasp clean` or deleted `node_modules`? `wasp install`.

## Verification

- **`wasp compile`** validates the spec and regenerates the SDK. It is the config check.
- Do **not** run `npx tsc -b` / `tsc` on the root `tsconfig.json` — the spec project pulls `src/` in without DOM libs and reports errors that aren't real. To check `src/` alone: **`npx tsc -p tsconfig.src.json`**.
- **`npm run check`** = brand-lint + security-lint + contrast + palette-mirror sync. Run it before considering any UI or operation change done.
- `wasp build` does **not** build the client bundle — `npx vite build` does. Both are needed to reproduce a ship.
- Tests: default is **zero** — a test must earn its place (money/permission/gnarly-pure logic). `npm run test` (vitest) from `app/`; it's deliberately not in `npm run check`. See [`docs/testing.md`](docs/testing.md).

## Key commands

```bash
# from app/
wasp start db                    # local Postgres (Docker), no DATABASE_URL needed
wasp db migrate-dev "msg"        # apply schema changes
wasp start                       # dev — :3000 client, :3001 server
wasp compile                     # validate config + regenerate SDK
npm run check                    # brand + security + contrast gates
npm run brand:mirror             # regenerate src/brand/palette.ts from Main.css
```

## Deployment gotchas

- **`app/public/Staticfile` is required** — do not delete. Railway/Railpack needs it (`root: .`, `index_fallback: true`) to serve SPA routes. See [`docs/deployment.md`](docs/deployment.md).
- `<script>` tags in the `head` array must use `async`, not `defer` (React hydration).
- `wasp build` refuses the `Dummy` email provider — that's the intended gate. Set a real provider before shipping (the `/ship` skill walks this).

## Skills

- **`/prototype`** — idea brief → renamed app + working screens. Run this first on a new idea.
- **`/brand`** — a brief → rewritten design tokens, fonts, palette; enforces WCAG AA + brand-lint.
- **`/ship`** — staged auth upgrade + deploy to Railway, with the security ship checklist.
